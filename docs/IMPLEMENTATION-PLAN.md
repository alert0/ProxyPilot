# ProxyPilot 实施开发计划

- 版本：V1
- 状态：M1 导入预览开发中
- 目标平台：Windows x64
- UI：Rust + Slint
- 本地后端：Rust
- 代理核心：官方 sing-box
- 首版目标：最多 10 个 HY2 节点、独立 SOCKS5 入口、每个入口显式绑定一个固定出站
- 原则：以真实代码、自动化检查和 Windows 实测结果验收；不把模拟界面当作功能完成。

## 0. 项目边界与固定决策

### 必须遵守

1. 保留现有 Windows + v2rayN，不替换、不修改其配置，不误杀其进程。
2. 默认监听 `127.0.0.1`；首版不做 TUN、不改系统代理。
3. 建议默认端口为 18001–18010，但每个端口均可检查冲突并安全调整。
4. 每个本地入口通过显式路由绑定到唯一出站；首版不做负载均衡、随机出口或自动故障转移。
5. 节点故障必须失败关闭，不允许静默切换到其他出口。
6. HY2 链接和配置中的密码属于敏感凭据；不得提交到 Git、打印到日志或默认导出。
7. 配置生成后必须使用选定版本的 `sing-box check` 校验，校验失败不得启动。
8. UI 的模拟数据必须有清晰标识；真实运行状态必须来自后端。
9. 未实际执行的构建、测试和代理验收不得标记为通过。

### 首版不做

- 替代 v2rayN 或实现新的代理协议
- 系统级透明代理 / TUN
- 云端同步、远程控制、账号体系
- 自动 IP 轮换、自动故障转移
- 浏览器指纹修改
- 在没有真实节点的情况下宣称代理、DNS 或 WebRTC 验收通过

## 1. 里程碑总览

| 阶段 | 目标 | 交付物 | 验收门槛 |
|---|---|---|---|
| M0 | 工程骨架 | Rust + Slint、CI、基础页面 | Windows CI 的 fmt、check、test、Clippy 全部通过 |
| M1 | 节点管理 | HY2 链接导入、解析预览、节点列表 | 解析测试通过，秘密脱敏 |
| M2 | 配置引擎 | 端口映射、配置生成、配置校验 | 1、2、10 节点 fixture 校验通过 |
| M3 | 核心生命周期 | 下载/选择核心、启动/停止、端口冲突 | 只管理自己的进程，不影响 v2rayN |
| M4 | 真实连通性 | 单节点/批量测试、出口 IP 和耗时 | 每个入口独立测试并记录证据 |
| M5 | DNS 与故障隔离 | DNS 诊断、节点故障注入与恢复 | 无静默切换，其他节点不受单节点故障影响 |
| M6 | Windows 发布 | 安装包/便携包、版本信息、许可声明 | 干净 Windows 环境安装与升级验收 |

## 2. M0 — 工程骨架与 CI

### 任务

- 初始化 Rust + Slint 工程。
- 建立 Rust 格式检查、编译、测试和 Clippy 检查。
- 建立 Rust format、clippy、test 检查。
- 配置 GitHub Actions，在 PR 和主分支推送时运行检查。
- 保留已有设计文档；新增开发说明、贡献说明和忽略文件。
- 创建中文桌面布局：运行概览、代理节点、端口映射、诊断与验收、运行日志、设置。
- 仅使用演示数据，并在 UI 中持续显示“演示 / 尚未连接真实核心”。
- 定义 Rust 应用模块边界和 UI 回调接口。

### 验收

- 新克隆仓库后可按 README 安装并启动开发模式。
- Rust fmt、cargo check、cargo test、Clippy 在 CI 中执行。
- 界面所有按钮要么有真实作用，要么明确标记为未接入，不允许假成功。
- 不包含真实节点链接、凭据、生产配置或本机日志。

## 3. M1 — HY2 分享链接导入与节点管理

### 任务

- 支持粘贴多条 `hy2://` / `hysteria2://` 链接（一行一条）。
- 支持标准 / URL-safe Base64（有无 padding 均可）的链接列表，忽略 Base64 中的空白和换行。
- 后续补充从纯文本文件导入。
- 对每条链接分别解析并返回成功、警告或失败。当前 UI 以状态消息展示摘要；节点列表和逐行状态仍待实现。
- 支持编辑名称、启用/禁用、删除和重复节点提示。
- 展示服务器、端口、TLS SNI、混淆配置是否存在等非秘密字段。
- 密码、混淆密码和含凭据的原始 URL 默认掩码。
- 使用纯虚构链接建立测试 fixture，不使用真实生产凭据。
- 对百分号编码、IPv4/IPv6 主机格式、缺字段、重复参数、未知参数和异常 URL 做单元测试。
- 仅映射当前 sing-box 版本已确认支持的字段；遇到未知安全相关参数时必须提示，不能静默丢弃。

### 验收

- 导入 10 条有效测试链接后，显示 10 条对应节点且字段匹配。
- 非法链接只影响对应行，不使整个导入流程崩溃。
- UI、错误信息、日志和导出诊断中不出现密码或完整分享链接。
- 解析器不声称已测试节点连通性。

## 4. M2 — 端口映射与配置生成

### 任务

- 建立稳定的 Node、Endpoint/ProfileMapping、TestResult 数据模型。
- 默认建议端口 18001–18010；检查重复、越界和本地占用。
- 允许每个 Profile 绑定一个节点，并清楚展示映射关系。
- 从类型化数据生成 sing-box JSON；禁止直接拼接用户输入为 JSON。
- 为每个入口生成唯一 tag，为每个节点生成唯一 outbound tag。
- 生成显式 inbound-to-outbound 路由规则；不得用通用兜底出口掩盖映射错误。
- 监听地址默认固定为 `127.0.0.1`。
- 生成配置前检查所有启用的入口都有明确的目标节点。
- 原子写入配置、限制 Windows 文件权限，并保留上一个有效配置用于回滚。
- 通过选定版本的 sing-box 执行配置校验。

### 验收

- 1、2、10 个节点的测试数据均能生成合法配置。
- 每个启用入口恰好对应一个预期出站。
- 无重复 tag、端口或映射。
- 未知节点、无效端口、缺少必填参数或校验失败均阻止启动。
- 测试配置中没有真实秘密；生产配置不进入 Git。

## 5. M3 — sing-box 核心生命周期

### 任务

- 提供官方核心版本和架构信息，校验所选二进制路径及版本。
- 明确采用下载官方发行包或用户选择本地二进制的策略；下载时验证官方校验信息。
- Rust 后端通过固定可执行路径和参数数组启动进程，不使用 shell 拼接。
- 记录当前应用启动的子进程句柄 / PID，并采集经过脱敏的 stdout/stderr。
- 提供启动、停止、重启、状态检查。
- 启动前检测端口冲突；报告占用端口及可获得的进程信息，不自动杀进程。
- 处理启动失败、异常退出、停止超时和配置回滚。
- 不修改系统代理、Windows 防火墙、TUN 或 v2rayN。

### 验收

- 只有配置校验成功后才启动核心。
- 停止 ProxyPilot 不会终止其他 sing-box 或 v2rayN 进程。
- 端口冲突时安全失败，不会自动结束占用端口的程序。
- 真实进程状态与 UI 一致；异常退出有明确错误。
- 所有日志均经过秘密脱敏。

## 6. M4 — 真实连通性和出口 IP

### 任务

- 为每个本地 SOCKS5 端口发起真实 HTTPS 测试请求。
- 记录开始/结束时间、退出码、耗时、观察到的出口 IP、测试服务和错误类别。
- 支持单节点测试与批量测试，限制并发并设置超时。
- 分别区分端口监听、代理连接、出口 IP 查询和测试服务错误。
- 记录结果时间，明确显示“最近一次测试”，不将历史结果伪装为实时状态。

### 验收

- 10 个入口逐个发起请求，结果与其实际路由相符。
- 同一出口 IP 可以合法地被多个节点共享，不能将“IP 不同”作为唯一成功标准。
- curl/测试进程的退出码、stdout、stderr 均被正确处理。
- 测试服务不可用时标记为测试服务错误，不误判为节点故障。
- 未成功获得响应和有效 IP 时不得显示测试通过。

## 7. M5 — DNS 诊断与故障隔离

### 任务

- 区分代理服务器主机名解析、SOCKS 远程解析、浏览器 DoH 和系统 DNS。
- 提供每个目标 Profile 的人工浏览器检查步骤。
- 可选集成公开 DNS 检测服务，但记录服务名称、时间和测试限制。
- 提供受控单节点故障测试、恢复步骤和测试前后结果比较。
- 验证节点故障后对应入口失败关闭，不转移到其他出站。
- 验证其他节点仍能独立完成请求。
- 诊断报告默认脱敏，清理测试用临时网络规则。

### 验收

- 不以单次 `socks5h` 请求或单一网页结果宣称浏览器“DNS 无泄漏”。
- 节点 A 故障不会让 Profile A 静默使用节点 B 的出口。
- 节点 B–J 在各自链路健康时继续正常工作。
- 恢复节点 A 后，其端口回到原绑定，出口与基线匹配。
- 所有故障注入均有用户确认和恢复步骤。

## 8. M6 — Windows 发布与升级

### 任务

- 构建 Windows x64 安装包或便携包。
- 验证首次安装、启动、导入、配置校验、停止、卸载。
- 添加版本号、变更日志、第三方许可证和 notices。
- 明确 sing-box 的获取、完整性校验、更新与回滚策略。
- 实现本地元数据备份；默认不导出明文秘密。
- 文档说明数据目录、日志位置、删除数据和恢复配置的方法。

### 验收

- 在干净 Windows 环境完成安装和启动。
- v2rayN 保持可用且配置不变。
- 安装包及依赖许可证审查完成。
- 生成配置、日志、诊断包的文件权限与脱敏经过实测。
- 发布说明列明测试过的 Windows 版本、sing-box 版本、已知限制和验收证据。

## 9. 测试分层

- 单元测试：链接解析、数据模型、端口分配、路由映射、秘密脱敏。
- 配置测试：对 1/2/10 个虚构节点生成配置并调用固定版本核心校验。
- 集成测试：临时目录、模拟进程、端口占用、进程异常退出、配置回滚。
- Windows 手工验收：真实核心启动、真实节点连通性、出口 IP、DNS 路径和故障隔离。
- CI 不依赖真实 HY2 凭据；真实节点测试使用用户本地环境，不上传节点秘密。

## 11. 实施顺序与完成定义

执行顺序：M0 → M1 → M2 → M3 → M4 → M5 → M6。

每个里程碑完成时必须同时提交：
- 实际代码和必要文档
- 自动化测试
- 本阶段验收命令及结果
- 已知限制和未解决问题
- 相关 GitHub commit

仅创建 UI、仅能编译或仅能监听本地端口都不算完成真实代理功能。M4/M5 必须有真实请求与测试记录，M6 必须有 Windows 实测记录。
